# C1.8 — Harness de humo multi-peer (Play Mode test)

Fase 1 · P3 · Worker: Sonnet · Auditor: Opus · Iteraciones máx: 3

## Objetivo
Probar sin personas lo que más se rompe: tomar, soltar, colocar y que nada flote, con varios peers a la vez. Los clones de Multiplayer Play Mode fallan en esta máquina (base de assets en sólo lectura), así que el harness corre **varios `NetworkRunner` en un solo proceso** (multi-peer de Fusion) dentro de un test de Play Mode del Unity Test Framework. Métrica: `unity test` en modo PlayMode pasa en verde y detecta una regresión si se rompe tomar/soltar/colocar.

## Lee antes
`CLAUDE.md`, `Docs/plan/README.md`, `Networking/ConnectionManager.cs` (cómo arranca una sesión Shared y la escena), `Networking/PlayerSpawner.cs`, `Interaction/Carryable.cs` y `Interaction/PlayerInteractor.cs` (API pública que llama la capa de input: `Interact`, `RequestRelease`, `CanInteract`), `Fireplace/FireplaceManager.cs` (`RequestPlace`, `CanPlace`), `Diagnostics/GroundingAudit.cs` (medida de «flota»), el SDK en `Assets/Photon/Fusion` sólo para la API de multi-peer (`NetworkProjectConfig.PeerMode`, `StartGameArgs`, `NetworkRunner.GetRunnerForGameObject`/escenas por runner).

## Cambios exactos
1. **Nuevo** asmdef de tests `Assets/_Project/Tests/PlayMode/BetterTogether.Tests.PlayMode.asmdef` (referencias: UnityEngine.TestRunner, UnityEditor.TestRunner, Fusion.Runtime y el ensamblado del juego — si el juego está en Assembly-CSharp sin asmdef, un asmdef de test no puede referenciarlo: en ese caso crear el test **sin** asmdef bajo `Assets/_Project/Tests/PlayMode/` con `[UnityTest]` y documentarlo; elegir la opción que compile).
2. **Nuevo** `SmokeMultiPeerTests.cs`: un `[UnityTest]` (timeout 120 s) que:
   - Pone `PeerMode = Multiple` **sólo en runtime** sobre la config global (sin guardar el asset; restaurar al terminar).
   - Arranca 2 runners en modo Shared en una sala única (`"HARNESS" + Guid`), cargando `CampBryan`, espera a que ambos tengan su jugador.
   - Elige el `Carryable` de 1 portador más cercano (salchicha o fósforos) y, en el peer **no master**, llama a la misma API que usa el input para tomarlo; espera ≤ 2 s y comprueba en **ambos** peers que el objeto está sostenido por ese jugador.
   - Suelta (misma API); espera 3 s; comprueba en ambos peers que no está sostenido y que su altura sobre el suelo (raycast hacia abajo, máscara Environment) es < 0,05 m y la diferencia de posición entre peers < 0,10 m.
   - Apaga ambos runners y limpia.
   - Si no hay red (sin conexión a Photon), `Assert.Ignore` con mensaje claro en vez de fallar.
3. Documentar en la tarjeta cómo ejecutarlo: `unity test <proyecto> --mode PlayMode` (con el editor cerrado) o desde el Test Runner.

## Qué NO hacer
No modificar `Assets/Photon` ni guardar `NetworkProjectConfig`. No refactorizar el input del juego. No tocar escenas ni prefabs.

## Validación
- V1: el test restaura la config y apaga los runners incluso si falla (try/finally); sin `Thread.Sleep` (usar `yield`); no depende del orden de spawn.
- V2/V0: el orquestador lo ejecuta en el editor (Test Runner vía CLI) y debe pasar.

Reporte ≤ 20 líneas.

## Cómo ejecutarlo (implementado)
- Editor cerrado: `unity test <proyecto> --mode PlayMode --filter SmokeMultiPeerTests` (o `Tools/compile-check.ps1` sólo compila). Con el editor abierto: Window > General > Test Runner > PlayMode > `BetterTogether.Tests.PlayMode`.
- Necesita red a Photon; sin ella el test se marca Ignored (no falla). Usa una sala única por ejecución y no guarda `NetworkProjectConfig`.
- Sin asmdef del juego (el código vive en Assembly-CSharp y un asmdef no puede referenciarlo): el asmdef de tests sólo referencia Fusion y alcanza los tipos del juego por reflexión (`Game` dentro del test). Si algún día se crea un asmdef del juego, sustituir la reflexión por referencias directas.
- Cada objeto se asigna a su peer por `NetworkBehaviour.Runner` (nunca por estáticos como `PlayerInteractor.Local`); la copia del otro peer se halla con `runner.TryFindObject(Object.Id)`.
- El test arranca la partida (`MatchManager.StartMatch`) porque `AllowsInteraction` exige fase Playing.
